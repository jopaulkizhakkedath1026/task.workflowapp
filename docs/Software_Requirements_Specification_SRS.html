1. Introduction

1.1 Purpose

This Software Requirements Specification (SRS) formally describes the system requirements, architectural specifications, interface protocols, and verification criteria for the Employee Management Portal developed during the ICT Academy of Kerala Summer Internship program.

1.2 Scope of the Application

The system is a decoupled Single Page Application (SPA) powered by the MERN stack (MongoDB, Express.js, React.js, Node.js). The application serves as an enterprise workforce management dashboard enabling authorized users to manage employee profiles, track designations, analyze office postings, and record salary structures.

2. Project Definition

2.1 Problem Statement

Problem Statement: Traditional spreadsheet-based employee records suffer from data inconsistency, absence of validation guards, concurrent editing conflicts, and a lack of responsive centralized access. The Employee Management Portal provides a cloud-backed, secure REST API and reactive web interface to streamline workforce record administration.

2.2 Target Users & Roles

User Role Description Access Rights
HR Administrator Primary manager maintaining workforce database Full CRUD privileges: Add, edit, list, and delete employee records.
Department Lead Supervisory viewer monitoring workforce distributions Read-only privileges: Browse directory, filter/view single records.

3. User Stories & Acceptance Criteria

  • Story 1 (List All Employees): As an HR Administrator, I want to view a comprehensive list of employees so that I can audit current organizational staffing.
    Acceptance Criteria: Page load triggers GET /api/employeelist; shows animated loader; displays table on success; displays empty state if 0 records; displays error banner if API is unreachable.
  • Story 2 (Create Employee): As an HR Administrator, I want to add a new employee profile with name, location, position, and salary.
    Acceptance Criteria: Input validation requires all fields; submits via POST /api/employeelist; disables submit button while pending; updates directory table without page reload.
  • Story 3 (Lookup by ID): As a Team Lead, I want to view a single employee's profile by ID.
    Acceptance Criteria: Fetches via GET /api/employeelist/:id; returns 200 with object; returns 404 for non-existent IDs.
  • Story 4 (Update Employee): As an HR Administrator, I want to edit designation or compensation parameters.
    Acceptance Criteria: Modal pre-fills existing values; sends PUT /api/employeelist/:id; returns updated object with HTTP 200.
  • Story 5 (Delete Employee): As an HR Administrator, I want to remove a decommissioned staff record.
    Acceptance Criteria: Sends DELETE /api/employeelist/:id; removes entry from table dynamically.

4. System Architecture & Project Structure

The application strictly adheres to the MERN three-tier decoupled architecture:

Data Flow: Browser Client (React SPA) ➔ HTTP REST Requests (JSON) ➔ Express/Node API Server ➔ Mongoose ODM Queries ➔ MongoDB Atlas Cloud Database.

6. API Contract Specification

Method & Path Functionality Request Payload Success Code Error Codes
GET /api/employeelist Retrieve all employee records None 200 OK (Array) 500 Server Error
GET /api/employeelist/:id Retrieve single employee by ID None 200 OK (Object) 400 Invalid ID, 404 Not Found
POST /api/employeelist Create new employee record JSON: name, location, position, salary 201 / 200 (Object) 400 Missing/Invalid Fields
PUT /api/employeelist/:id Update employee information JSON: modified fields 200 OK (Object) 400 Invalid Input, 404 Not Found
DELETE /api/employeelist/:id Delete an employee record None 200 OK 400 Invalid ID, 404 Not Found

7. Non-Functional Requirements

  • Performance: Initial page load time < 2 seconds; API response time < 300ms.
  • Security: All credentials isolated in .env; CORS configured; inputs parsed and sanitized.
  • User Experience: Responsive layout supporting mobile, tablet, and desktop viewports. Explicit loading, empty, and error feedback states.
  • Reliability: Graceful catch handlers on all asynchronous database queries to prevent server crashes.
